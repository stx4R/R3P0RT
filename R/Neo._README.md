# Neo.

해외 **수출 규제**를 "이 법이 바뀌었다"가 아니라 **"그래서 당신은 이걸 해야 한다"** 로 변환하는 PWA를 만든 프로젝트.
법률·규제 대응팀이 없는 수출 중소기업 담당자를 사용자로 놓고,
4개 도착국 × 3개 품목의 **법령 61건 · 실행 항목 174건**을 사람이 조사·교차검증해 정적 데이터셋으로 구축했으며,
백엔드 없이 **설치 후 네트워크가 끊겨도 전 화면이 열리는** 소프트웨어로 구현하였다.

---

## *Motive.*

수출은 물건을 배에 싣는 일이 아니라 **도착국의 규제를 통과하는 일**이다.
그런데 그 규제는 국가별·품목별로 갈라져 있고, 원문은 베트남어·일본어·인도네시아어로 되어 있으며, 예고 없이 바뀐다.

대기업에는 이걸 전담하는 팀이 있다. **중소기업에는 없다.**
수출 담당자는 대개 품질이나 영업을 겸하고 있고, 법률 전문가가 아니며, 조문을 읽을 시간이 없다.
그런데 **실수의 대가는 크다** — 통관 거부, 리콜, 과징금.

정보가 없어서 생기는 문제가 아니다. 법령은 관보에 공개되어 있다.
문제는 **"그래서 우리 제품에 걸리는가"** 를 아무도 알려주지 않는다는 것이다.

> 🎯 **핵심 명제**
> **"이 법이 바뀌었다"가 아니라 "그래서 당신은 이걸 해야 한다"를 판다.**

법령 뉴스레터는 이미 많다. 이 앱이 팔아야 할 것은 정보가 아니라 **변환**이다 —
조문 → 우리 제품에 걸리는지 → 그래서 무엇을 언제까지 해야 하는지.

### *Purpose.*

법률 비전문가가 **조문을 읽지 않고도** 수출 전 필요한 조치를 확인하고 완료할 수 있게 한다.
동시에 그 변환의 근거(어느 출처를, 언제, 무엇을 확인해 그렇게 판정했는지)를 **전부 추적 가능하게 남겨**,
앱이 지어낸 값을 사실처럼 보여주지 않도록 설계하는 것을 목적으로 한다.

## *Research Q & H.*

> 법령을 실행 항목으로 변환할 수 있는가? 그리고 그 변환을 자동화하지 않는 것이 오히려 더 정확한가?

- **가설 1 (변환 가능성)** — 법령을 `무엇을 · 누가 · 언제까지`의 실행 항목으로 분해하면, 비전문가도 조문 해석 없이 조치를 수행할 수 있을 것이다.
- **가설 2 (매칭 키)** — 법률과 제품을 잇는 실제 키는 품목 분류가 아니라 **HS 코드**이며, 여기에 **도착국 × 품목 × 출발국** 세 축이 더해져야 "우리에게 걸리는가"가 판정될 것이다.
- **가설 3 (수동 데이터의 우위)** — 법령 데이터베이스를 자동 수집하는 것보다, 사람이 독립 출처 2개 이상으로 교차검증한 정적 데이터셋이 **더 정확할** 것이다.
- **가설 4 (오프라인 성립)** — 백엔드 없이 정적 데이터와 직접 작성한 서비스워커만으로, 설치 후 네트워크가 끊겨도 전 화면이 동작할 것이다.
- **가설 5 (파생값 원칙)** — 화면의 모든 수치를 데이터에서 계산하면, 상태가 바뀔 때 화면이 거짓말을 하는 것이 **구조적으로 불가능해질** 것이다.

검증은 각각 ▲법령당 실행 항목의 실제 생성과 화면 도달 경로, ▲HS 접두 매칭의 데이터 검사 통과, ▲조사 규칙 7항과 제외 사유 기록, ▲빌드 후 서버 종료 상태에서의 전 화면 열람, ▲검산에서 드러난 아트보드 수치 오류로 확인하였다.

## *Domain.*

### *지원 범위 — 국가가 아니라 조합이다*

| | 식품·음료 | 화장품 | 전기·전자 |
|---|:---:|:---:|:---:|
| **VN** 베트남 | 4 | 4 | 5 |
| **JP** 일본 | 5 | 5 | 4 |
| **US** 미국 | 5 | 5 | 4 |
| **ID** 인도네시아 | 4 | 4 | 4 |

**같은 나라라도 품목마다 규제의 축이 다르다.**
베트남 화장품은 *제품신고*가 벽이고, 일본 화장품은 *라벨이 아니라 처방과 등록*이 벽이며,
베트남 전기·전자에 와서야 **HS 코드에 따라 요건이 갈리는 사례가 처음 실재**했다.
그래서 데이터의 단위를 국가가 아니라 **국가 × 품목 조합**으로 잡았다.

### *공용 법령 — 품목을 가리지 않는 것들*

조합 12개 위에 국가별 **공용 법령 8건**이 얹힌다. 화면에는 둘이 합쳐져 뜬다.

| 국가 | 공용 법령 | 성격 |
|---|---|---|
| VN | 상품 라벨 규정 전면 개정 (전자라벨 도입) · 생산자책임재활용(EPR) | 라벨 · 포장 |
| JP | 포장재 식별마크 의무 · 용기포장 재상품화 의무 | 포장 |
| US | **강제노동 추정 배제** · 원산지 표시 · **한미 FTA 특혜관세** | 통관 · 원산지 |
| ID | **할랄 인증 의무** | 인증 |

공용 법령을 조합 파일마다 복사하지 않은 이유는 **법령 id가 전역에서 유일해야** 상세 페이지 정적 생성과 id 조회가 성립하기 때문이다.
복사하면 id 하나가 서로 다른 실행 항목 집합 여럿을 가리키게 된다.
대신 **실행 항목 쪽에 품목을 달았다** — 화장품 사용자에게 식품 액션이 섞이지 않는다.

### *`originScope` — 출발국이 요건을 가른다*

수출 규제는 도착국만의 문제가 아니다. **한미 FTA 특혜관세**는 출발국이 한국일 때만 성립한다 —
원산지증명서를 수출자가 직접 작성하고 5년간 보관해야 한다는 요건은, 다른 나라에서 보내면 아예 존재하지 않는다.

```
laws.filter(law => !law.originScope || law.originScope.includes(profile.originCountry))
```

`originScope`가 없으면 출발국과 무관하고, 있으면 그 출발국일 때만 노출된다.
**출발국을 바꿨는데 아무것도 안 바뀐 척하지 않고, 반대로 바뀐 척도 하지 않는다** —
빠진 법령 수를 세어 목록 하단에 한 줄로 적는다.

### *HS 코드가 실제 매칭 키다*

품목 분류("화장품")는 사람이 읽는 이름이고, 법령이 실제로 지목하는 것은 **HS 코드**다.
한 법령이 `["16","17","18","19","20","21","2202"]` 같은 접두 목록을 들고 있고, 제품의 HS 코드가 그중 하나로 시작하면 걸린다.

접두 길이가 다른 것이 요점이다 — `21`은 류(2자리) 전체, `2202`는 호(4자리) 단위다.
**법령이 규정한 만큼만 좁힌다.** 없는 세분을 지어내면 걸리지 않는 제품을 걸리게 만든다.

### *위험도와 상태*

`위험도 = 제재 강도 × 대응 시급성(D-Day) × 자사 제품 해당 범위`

3축 곱으로 산정하되 **화면에는 4단계 라벨만 노출**한다. 담당자가 알아야 할 것은 곱셈이 아니라 순서다.

상태는 한자 마커 세 글자로 표시한다 — `施`(시행중) · `留`(보류) · `豫`(예정).
텍스트가 아니라 **기호로 읽히게** 하는 것이 목적이라 글꼴 폴백을 명시적으로 유지했다.

## *Data.*

### *⚠ 실시간 수집이 아니다 — 그리고 그것이 더 정확하다*

**이 앱의 법령 데이터는 사람이 조사해 검증한 정적 데이터셋이다.**

숨길 이유가 없다. 자동 수집은 **"이 법이 우리 제품의 HS 코드에 걸리는가"** 와
**"이 날짜가 우리 품목의 날짜인가"** 를 판정하지 못하기 때문이다.

### *조사 규칙 7항*

| # | 규칙 |
|:---:|---|
| 1 | **모르는 건 비운다. 지어내지 않는다.** 이 프로젝트에서 가장 큰 실패는 그럴듯한 값을 채우는 것이다 |
| 2 | **독립된 출처 2개 이상 교차확인.** 번호·시행일·핵심 변경이 일치해야 기록한다 |
| 3 | **1차 출처와 2차 출처를 구분해 화면에 표시한다.** 2차를 1차인 척하지 않는다 |
| 4 | **`최종 확인` 날짜는 그 URL을 실제로 연 날이다.** 임의의 날짜를 넣지 않는다 |
| 5 | **기한은 법령에 명시된 것만.** 없으면 비운다. 화면 숫자를 맞추려고 역산하지 않는다 |
| 6 | **그 날짜가 우리 제품의 날짜인지 확인한 뒤에 넣는다** |
| 7 | **제외한 법령과 그 사유까지 기록한다** |

⑥은 가정이 아니라 실제로 발생한 함정이다 — **법령에 적힌 날짜가 다른 품목의 유예 종료일인 경우**가 있었다.
그 날짜를 그대로 넣었다면 담당자는 존재하지 않는 마감에 맞춰 움직였을 것이다.

⑦이 데이터셋의 성격을 결정한다. 조사 문서에는 **채택한 법령**만이 아니라
**제외한 법령과 그 사유**(초안 단계라 확정 아님, 의무자가 수입자라 수출자 의무가 아님, 이미 다른 법령에 포함됨 등)와
**확인하지 못해 비워 둔 값**까지 적혀 있다. 없는 것을 없다고 적는 것이 이 데이터셋의 방법론이다.

### *규모*

| 항목 | 값 |
|---|---|
| 조합 | **16개** (12조합 + 공용 4파일) |
| 법령 | **61건** (조합 53 + 공용 8) |
| 실행 항목 | **174건** |
| 출처 | **1차 47 / 2차 14** |
| 상태 | 시행중 60 · 보류 1 |

1차 출처는 관보·소관 부처 원문이고, 2차 출처는 로펌·법률DB·시험인증기관이다.
화면은 이 구분을 **배지로 인쇄**한다 — 사용자가 "이 정보를 얼마나 믿을지"를 스스로 판단할 수 있어야 한다.

## *Software.*

### *① 아키텍처 — 백엔드가 없다*

| 항목 | 값 |
|---|---|
| 스택 | Next.js App Router + TypeScript |
| 데이터 | 정적 JSON + `localStorage`. **서버 0** |
| 런타임 의존성 | `next` · `react` · `react-dom` · `d3-geo` · `topojson-client` **다섯뿐** |
| 컴포넌트 | **전부 직접 작성** — UI 라이브러리·바텀시트 라이브러리 미사용 |
| PWA | **손으로 쓴 서비스워커.** 프레임워크 플러그인 미사용 |
| 지도 | 원본 스크립트를 npm 패키지로 포팅. **CDN 의존 0** |

계획서는 컴포넌트 라이브러리 도입을 적었지만 쓰지 않기로 판정했다.
디자인 규칙이 `box-shadow` 전역 금지 · `border-radius: 0` · 카드 박스 금지 · 둥근 pill 금지로 되어 있어,
라이브러리를 들여와도 **기본 스타일을 전부 벗겨내야** 했기 때문이다.

CDN 의존을 0으로 만든 것은 취향이 아니라 **오프라인 요구사항에서 나온 결정**이다.
지도 데이터·폰트·아이콘을 전부 정적 파일로 포함했고, 그래서 오프라인에서 지구본이 그대로 그려진다.

### *② `Dataset` — 전역 가변 상태를 두지 않는다*

화면은 "현재 데이터셋"이라는 전역 변수를 보지 않는다.
프로필(도착국 · 품목 · 출발국 · 제품 목록)이 가리키는 **조합 하나를 펼친 값**을 인자로 받는다.

```ts
interface Dataset {
  profile, today, country, category
  laws, actions, products      // 출발국 필터를 이미 통과한 것
  hiddenByOrigin: number       // originScope로 빠진 법령 수
  empty: boolean               // 이 조합에 데이터가 아예 없는가
}
```

전역 가변 상태를 React가 읽으면 **화면마다 다른 시점의 값을 볼 수 있다.**
또한 `null`은 "데이터 없음"이 아니라 **"아직 모른다"** 를 뜻한다 — 프로필은 `localStorage`에 있고
하이드레이션 렌더에서는 읽히지 않는다. 그 한 프레임 동안 화면은 스켈레톤을 그린다.
**없는 데이터를 0으로 채우지 않는다.**

### *③ 파생값 원칙 — 화면의 숫자는 전부 계산된다*

디자인 산출물에 박혀 있던 숫자들(`대응 필요 3건`, `MUST DO — 4`, `규제 5 · 미완 액션 10`)을 **전부 데이터에서 계산**하도록 바꿨다.

문자열로 박으면 사용자가 액션 하나를 체크하는 순간 **즉시 거짓말이 된다.**

> **검산에서 아트보드가 틀린 것이 드러났다.**
> `규제 5 · 미완 액션 10` — 실제로는 법률 5건, 전체 액션 **9건**이었다.
> 파생값으로 처리하면 이런 오류가 애초에 발생하지 않는다. → **가설 5 지지**

같은 원칙이 날짜에도 적용된다. 아트보드의 `D-45` · `D-14`는 목 데이터에 맞춰 그린 **허구값**이라 폐기했다.
배지는 **실재하는 날짜에서만** 나온다.

| 조건 | 배지 |
|---|---|
| 법령에 명시된 기한이 있다 | 그 날짜까지 카운트다운 |
| 기한이 없는데 이미 시행 중이다 | **`미이행`** |
| 아직 시행 전이다 | 시행일까지 카운트다운 |
| 보류 법령이다 | **배지 없음** — 언제까지 해야 하는지 아무도 모른다 |

두 번째 항목이 미묘한 지점이다. 시행일이 지난 상시 의무에 **`기한 경과`** 를 붙이면 틀린 말이 된다 —
놓친 날짜가 있는 게 아니라 **이미 지켜야 하는 의무를 아직 안 한 것**이다.
색은 그대로 최고 위험이다. 지금 위반 상태라는 사실은 달라지지 않는다.

상단바의 시각도 마찬가지다. 예전에는 "마지막 동기화"로 찍었는데 **동기화하는 서버가 없으므로 그건 지어낸 시각**이었다.
실제로 말할 수 있는 것은 **"우리가 이 출처들을 언제 열어 봤는가"** 뿐이다.

### *④ 데이터 무결성 검사기*

화면이 데이터를 믿고 그리므로 **참조가 끊기면 조용히 빈칸이 되거나 크래시한다.**
타입 검사는 JSON을 통과시키지 못하므로(임포트 시 문자열로 넓어진다) 별도 검사기를 두었다.

| 층 | 검사 항목 |
|---|---|
| 국가 | 코드 2글자 대문자 · 중복 · 위경도 범위 · 지원 여부 정합 |
| 품목 | HS 코드가 4자리 또는 6자리 · 품목 접두 범위 안 |
| 법령 | id 형식 · 위험도/상태/출처등급 열거값 · 보류면 보류일 필수 · 출처 URL·최종확인일 필수 |
| 법령 ↔ 품목 | HS 접두가 품목 범위 밖이면 실패 · 공용 파일인데 품목이 하나뿐이면 실패 |
| 법령 ↔ 액션 | 액션 id가 실재하는가 · **한 액션이 두 법령에 걸려 있으면 실패** · 어느 법령에도 안 걸린 액션이 있으면 실패 |
| 액션 ↔ 품목 | 액션이 법령에 없는 품목을 가리키면 실패 · 조합 파일 액션에 품목을 달면 실패 |
| 출발국 | `originScope`의 국가 코드가 실재하는가 |

조합을 하나 완성할 때마다 돌린다. 현재 **참조무결성 통과**.

### *⑤ 오프라인 — 실측이 설계를 뒤집었다*

계획서는 `data/*.json`을 캐싱하라고 적었지만 **그 조건이 성립하지 않았다.**
그 JSON은 정적으로 임포트되어 JS 청크 안에 들어 있고 **독립된 URL이 없다.**
캐싱할 수 있는 것은 실제로 URL을 갖는 것뿐이다.

더 큰 문제는 그다음이었다.

> **cache-first 런타임 캐싱만으로는 부족했다.**
> 그것은 **실제로 요청된 것만** 담으므로, **온라인에서 이미 열어 본 화면만** 오프라인에서 열렸다.
> 프로덕션 빌드를 띄우고 홈만 연 뒤 서버를 내리니 다른 화면이 **청크 로드 실패로 빈 화면**이 됐다.

해법은 빌드 훅 없이 만들었다 — 프리캐시한 **문서 HTML에서 정적 청크 참조를 뽑아** 함께 담는다.
해시 파일명을 알기 위해 빌드 매니페스트를 생성할 필요가 없다.

| 구분 | 처리 |
|---|---|
| 설치 시 프리캐시 | 매니페스트 · 지도 데이터 · 폰트 3종 · 마커 글꼴 3종 · 아이콘 4종 |
| 라우트 문서 | **앱이 서비스워커에 알려준다** (URL이 고정되지 않으므로) |
| 클라이언트 내비게이션 페이로드 | **문서와 다른 캐시**에 담는다. 쿼리 해시가 빌드마다 달라 URL 완전 일치로 못 찾는다 |
| 해시 붙은 정적 자산 | cache-first — 한 번 받으면 다시 묻지 않는다 |

**검증 방법은 실제로 끊어 보는 것이다** — 빌드 후 서버를 띄우고 홈을 한 번 연 뒤 **서버를 내린다.**
현재 6화면 + 설정 + **법령 상세 61개가 전부 열린다.** 지도까지 그려진다. → **가설 4 지지**

### *⑥ 설치 가능성의 검증 기준을 바꿨다*

Lighthouse 12에서 PWA 카테고리가 제거되어 기존 검증 기준이 사라졌다.
대체 기준으로 **설치 프롬프트 이벤트가 실제로 발화하는 것**을 채택했다 —
브라우저는 매니페스트 필수 항목(이름·시작 URL·표시 모드·192/512 아이콘·마스커블)과
fetch 핸들러를 가진 서비스워커가 **모두** 통과할 때만 이 이벤트를 쏜다.
**"점수가 몇 점인가"가 아니라 "브라우저가 설치 가능하다고 판단하는가"** 를 직접 확인한다.

### *⑦ 접근성 — 맞바꾼 것을 적는다*

| 항목 | 결과 |
|---|---|
| 터치 타겟 | **44px** — 6화면 전수 측정. 시각 크기는 그대로 두고 히트 영역만 넓힌다 |
| 색 대비 | 위험도 색면 위 글자 전부 AA 통과 (**최저 5.05:1**) |
| 낮은 대비 토큰 | 3.36:1인 토큰은 메타·라벨에만 사용. 본문에 쓰인 두 곳은 **취소선이 함께 걸린 "지나간 상태"** 라 색만으로 정보를 전하지 않는다 |
| 모션 | `prefers-reduced-motion`에서 스켈레톤 펄스를 끈다 |
| **확대 금지** | **WCAG 1.4.4(200% 확대)에 어긋난다** |

마지막 항목을 숨기지 않았다. "앱처럼 다뤄지게 한다"는 요구를 우선한 **의도적 선택**이며,
대신 본문 최소 크기를 15px로 유지해 확대 없이 읽히게 했다. **되돌릴 때는 두 줄만 빼면 된다**고 문서에 적었다.

실기기 확인에서 나온 것도 있다 — `100dvh`가 특정 모바일 브라우저에서 굳는 문제,
안전영역을 아트보드의 고정값이 아니라 `env()`로 읽어야 한다는 것.
**브라우저 탭에서는 안전영역이 0이고, 그때 상태바 띠가 사라지는 것이 맞다** — 없는 상태바를 흉내 내면 빈 띠만 남는다.

| 항목 | 결과 |

| 화면 | Home / Laws / Law Detail / Company / Map / Notifications / Setup |

| 오프라인 | 6화면 + 설정 + 법령 상세 61개 전부 열림 (서버 종료 상태) |
| 검증 폭 | 402 · 375 · 1400 세 폭에서 조합을 바꿔가며 확인 |
| 런타임 의존성 | 5개 · CDN 의존 0 |

### *판정 기록을 문서로 남겼다*

디자인 산출물과 데이터가 어긋난 지점, 계획서와 다르게 간 지점을 **번호를 붙여 전부 기록**했다.
"아트보드가 틀렸다", "계획서의 이 조건은 성립하지 않는다", "이건 확인하지 못해 범위 밖으로 둔다"까지 적혀 있다.
**구현이 문서를 따르지 않은 곳마다 그 이유가 남아 있다.**

### *지원하지 않는 것을 화면에 남긴다*

지원하지 않는 도착국(중국·태국 등)도 설정 목록에 **흐리게 남긴다.**
**"왜 4개국뿐인가"에 정직하게 답하는 장치**다. 목록에서 아예 지우면 사용자는 그 나라가 규제가 없는 줄 안다.

## *Conclusion*

1. **팔아야 할 것은 정보가 아니라 변환이다.** 법령은 이미 공개되어 있다. 없는 것은 "그래서 우리 제품에 걸리는가"이고, 그 판정에는 HS 코드·품목·도착국·출발국 네 축이 전부 필요했다. → **가설 1·2 지지**
2. **자동 수집보다 사람이 정확하다 — 이 문제에서는.** 법령 원문은 자동으로 긁을 수 있지만, "이 날짜가 우리 품목의 날짜인가"는 판정할 수 없다. 실제로 다른 품목의 유예 종료일을 만났고, 규칙 ⑥이 그것을 걸렀다. → **가설 3 지지**
3. **없는 것을 없다고 적는 것이 데이터셋의 품질이다.** 채택한 법령보다 **제외한 법령과 그 사유**가 더 많은 지면을 차지한다. 비워 둔 값도 비워 둔 채로 기록했다. 그럴듯한 값을 채우는 것이 이 프로젝트에서 가장 큰 실패다.
4. **화면의 숫자는 전부 파생값이어야 한다.** 하드코딩된 수치를 계산으로 바꾸는 과정에서 아트보드의 수치 오류가 드러났다(10 → 9). 파생값은 정확할 뿐 아니라 **틀릴 수 없다.** → **가설 5 지지**
5. **오프라인은 캐싱 전략이 아니라 검증 방법의 문제였다.** cache-first는 "이미 열어 본 것"만 담는다는 사실이 실제로 서버를 내려 보고 나서야 드러났다. **끊어 보지 않은 오프라인은 오프라인이 아니다.** → **가설 4 지지**
6. **의존성을 늘리지 않는 것이 요구사항을 지키는 방법이었다.** CDN 의존 0은 취향이 아니라 오프라인 요구에서 도출됐고, 컴포넌트 라이브러리 미사용은 디자인 규칙에서 도출됐다. 런타임 의존성 5개는 결과지 목표가 아니었다.
7. **맞바꾼 것은 적어야 한다.** 확대 금지는 접근성 기준을 어긴 선택이다. 그것을 숨기고 "접근성 준수"라고 적는 대신, 어긴 기준의 번호와 되돌리는 방법을 함께 남겼다.

## *Limit & Plan*

- **법률 분석 엔진은 범위 밖이다** — 이 산출물이 검증한 것은 화면과 흐름의 정합성, 그리고 데이터 변환 방법론이다. 조문을 자동으로 해석하는 기능은 없으며, 있는 척하지도 않는다.
- **데이터 갱신 경로가 없다** — 정적 데이터셋이므로 법령이 바뀌면 사람이 다시 조사해 커밋해야 한다. 규모가 커지면 이 방식은 유지되지 않는다. 조사 규칙을 지킨 채로 갱신 주기를 관리하는 절차가 필요하다.
- **4개국 × 3품목** — 실제 수출 현장이 다루는 범위에 비하면 좁다. 조합 하나를 추가하는 비용이 곧 조사 비용이므로, 확장은 데이터 문제이지 코드 문제가 아니다.
- **출발국 데이터는 한국 기준뿐** — `originScope`를 가진 법령이 현재 1건(한미 FTA)이다. 다른 출발국을 고르면 그 법령이 빠지고 그 사실이 표시되지만, **다른 출발국 고유의 요건은 아직 데이터에 없다.**
- **사용자 검증 미실시** — 성공 기준으로 "신규 사용자가 60초 내 자사 영향 법률 1건과 액션 1건에 도달"을 세웠으나 실제 사용자 테스트를 하지 못했다. 화면 흐름 카운트로만 대리 확인했다.
- **접근성 부채 1건** — 확대 금지(WCAG 1.4.4)는 의도적으로 남긴 위반이다. 되돌리는 방법은 문서화되어 있으나 되돌리지 않았다.
- **알림은 화면뿐이다** — 기한이 다가오는 것을 앱이 먼저 알려주는 푸시 경로가 없다. 담당자가 앱을 열어야 D-Day를 본다. 이 앱의 명제("그래서 당신은 이걸 해야 한다")를 완성하려면 **앱을 열지 않아도 도달하는 경로**가 필요하다.

### *Term.*

- **HS 코드** — 국제통일상품분류체계. 국가마다 관세·규제를 이 코드로 지목한다. 앞 2자리가 류, 4자리가 호
- **FTA 원산지증명** — 특혜관세를 받기 위해 물품의 원산지를 증명하는 서류. 한미 FTA는 **수출자 자율 작성 + 5년 보관** 방식이다
- **EPR(생산자책임재활용)** — 포장재 등의 재활용 의무를 생산자·수입자에게 지우는 제도
- **경과규정 / 유예기한** — 새 법령이 시행되어도 일정 기간 구 규정을 인정하는 조항. **품목마다 종료일이 다를 수 있다**
- **관보** — 정부가 법령을 공식 공포하는 매체. 이 데이터셋의 1차 출처 기준
- **1차 출처 / 2차 출처** — 관보·소관 부처 원문 / 로펌·법률DB·시험인증기관 해설
- **통관 거부 · 리콜** — 규제 미준수의 대표적 결과. 이 앱이 막으려는 것
- **PWA** — 웹 기술로 만들어 설치·오프라인 동작이 가능한 앱
- **서비스워커** — 브라우저와 네트워크 사이에서 요청을 가로채는 스크립트. 오프라인 동작의 본체
- **프리캐시 / 런타임 캐싱** — 설치 시점에 미리 담는 것 / 실제 요청이 발생할 때 담는 것. **후자만으로는 열어 본 화면만 오프라인에서 열린다**
- **하이드레이션** — 서버가 그린 HTML에 클라이언트 자바스크립트를 붙이는 과정. 이 시점에는 브라우저 저장소를 읽을 수 없다
- **파생값** — 원본 데이터에서 계산되는 값. 하드코딩된 수치와 달리 상태가 바뀌어도 틀리지 않는다
- **참조무결성** — 한 데이터가 가리키는 다른 데이터가 실재하는가. 끊기면 화면이 조용히 빈칸이 된다
- **안전영역(safe area)** — 노치·홈 인디케이터를 피해야 하는 화면 여백. 고정값이 아니라 브라우저가 알려주는 값이다
